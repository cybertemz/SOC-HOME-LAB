# Wazuh Agent Deployment on Windows 10
## SOC Home Lab — Practical Deployment Record

## 1. Project Objective

This stage of the SOC home lab documents deploying a Wazuh agent to the Windows 10 virtual machine and verifying that it communicates with the Wazuh server.

The agent allows the endpoint to send configured security and system telemetry to Wazuh for central monitoring. This is a practical lab exercise, not a production deployment.

## 2. Lab Environment

| Component | Recorded value |
|---|---|
| Virtualization | VMware Workstation |
| Windows endpoint | Windows 10 Pro, version 10.0.19045.6466 (as displayed in the dashboard screenshot) |
| Wazuh server address shown in screenshots | 192.168.239.134 |
| Agent name | wazuhwindows10 |
| Agent ID | 001 |

The IP addresses shown are private lab addresses and may change if the virtual network uses DHCP. Do not use them as permanent addresses without checking the current VM configuration.

## 3. Deployment Procedure

### Step 1 — Generate the Windows agent command

In the Wazuh dashboard, open **Endpoints** and choose **Deploy new agent**. Select the Windows MSI package and configure the Wazuh server address and agent name.

The screenshot of the Wazuh deployment wizard shows the generated command using the manager address and the agent name `wazuhwindows10`. Use the command generated by the dashboard for the version actually deployed rather than copying an old command from a different Wazuh release.

Official reference: [Deploying Wazuh agents on Windows endpoints](https://documentation.wazuh.com/current/installation-guide/wazuh-agent/wazuh-agent-package-windows.html).

### Step 2 — Install the agent from elevated PowerShell

The screenshots show the Windows agent installation command being run in an Administrator PowerShell window. The installer was configured to communicate with the Wazuh manager at the lab address shown above.

The command in the screenshot uses the downloaded Wazuh MSI package and sets the manager address and agent name. Keep generated credentials and other secrets out of public documentation.

### Step 3 — Start the Wazuh service

The PowerShell screenshot shows this command:

```powershell
NET START Wazuh
```

The terminal returned **“The Wazuh service was started successfully.”** This is evidence that the Windows service started successfully.

### Step 4 — Check manager connectivity

The PowerShell screenshot shows a TCP connectivity test to the Wazuh server and a successful result (`TcpTestSucceeded: True`). The screenshot uses port 1515 for that specific test. This confirms that the tested TCP connection succeeded at that time; it should not be treated as a substitute for checking the agent's configured communication port and current connection state.

Wazuh's documentation describes agent connection verification through the dashboard, agent state, and network connection checks: [Wazuh agent connection](https://documentation.wazuh.com/current/user-manual/agent/agent-management/agent-connection.html).

### Step 5 — Verify the endpoint in Wazuh

The Wazuh Endpoints screenshot displays one agent:

- **ID:** 001
- **Name:** wazuhwindows10
- **Operating system:** Microsoft Windows 10 Pro
- **Group:** default
- **Status:** Active (1 active agent shown in the summary)

This is the key evidence that the agent was registered and was reporting as active in the dashboard when the screenshot was taken.
